1. Contexte métier

PyMart Retail multi-catégories. Le personnel exporte des extracts POS en fichiers texte.
Besoin managers Imports fiables, commandes traçables, rapports daily / monthly archivables et reproductibles.

Problème

  • Données sales : espaces, casse, colonnes manquantes, nombres / dates invalides
  • Sans validation → crash ou rapports faux

Séparation des concerns : CLI mince → services → models → I/O.

5. Import + string/list

Fichiers CSV-like séparés par | — un fichier par entité

  • split("|"), strip(), ignore lignes vides / # / header
  • " ".join(name.split()).title() — espaces multiples
  • replace("$",""), .upper() / .lower()
  • Colonnes manquantes → RecordFormatError
  • Nombres invalides / négatifs → DataValidationError
# pymart/io/parsers.py
line = raw.strip()
fields = [part.strip() for part in line.split("|")]
...
"sku": sku.upper(),
"name": " ".join(name.split()).title()

8. CLI — commandes

python -m pymart.cli --help

python -m pymart.cli import \
  --products data/products.txt \
  --customers data/customers.txt \
  --orders data/orders.txt

python -m pymart.cli order list
python -m pymart.cli order create --id 2002 --customer C1001 --sku NB-001 --qty 1

python -m pymart.cli report --type daily --date 2026-06-30 --out reports/
python -m pymart.cli report --type monthly --month 2026-06 --out reports/

Aussi : python -m pymart · option --store

Rapports (outputs minimum)

  • ✓ Daily sales → reports/daily/2026-06-30/daily_sales_....txt
  • ✓ Monthly summary → top produits / clients, période, calendrier
  • ✓ Stock levels → stock_levels_YYYY-MM.txt

Contenu daily

  • Report date, Generated at, Next review date
  • Orders / Revenue + détail lignes
  • Snapshot catalogue via describe() (polymorphisme)

Important : importer products + customers + orders avant de générer un rapport, sinon Orders: 0.
